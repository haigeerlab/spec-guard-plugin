# Plan: hosted-ticket-workflow

依据 [`spec/hosted-ticket-workflow.md`](../../spec/hosted-ticket-workflow.md)、
已接受的 Proposal #125 与设计记录。本 Plan 与能力图可在同一个晋级 PR 评审；
本 PR 不执行真实远端缺陷 Issue 写入。任务进度以本目录的 `todo.md` 为准。

## 实施顺序

```text
明确目标与只读查重 → 单条安全创建 → 讨论及交付收尾 → 双宿主和批次接入 → 完整验收
```

1. **只读目标与查重。** 从现有 `ticket` 入口取得精确平台、主机、项目和可见性，
   完整分页查询普通 Issue，排除 GitHub PR 和 GitLab 系统/私有 note。先用假提供方
   固定 `found/absent/unknown/conflict`、403、截断分页和重复标记的失败用例。
   验收：不完整查询绝不允许创建，Local 目标不因 Git remote 改路由。
2. **单条安全创建。** 为审查发现或直接事项取得稳定编号；展示精确目标、内容
   和标记，经授权后写入并读回。仅在必要时用最小私有意图支持跨会话对账，
   处理 linked worktree 串行化和响应丢失。验收：成功取得唯一远端身份；
   超时、多个命中或一次空查询不盲建第二条。
3. **讨论与交付收尾。** 对实质范围变化留可读评论并读回；按每个 Issue 的
   PR/MR 覆盖、合并、验证和当前状态对账，获关闭授权后逐项关闭并读回。
   验收：部分交付、待部署、人工修改和平台自动关闭不虚报完成。
4. **批次与双宿主入口。** 让 Claude/Codex 入口和审查检查点沿用批次目标、
   稳定发现编号及剩余数量；更新使用文档。验收：审查冻结后的多轮“继续”
   进入逐项处理；只读审查不建单，GitHub 仓库选 Local 仍走 Epiq。
5. **真实验证与回归。** 先运行假提供方正反用例，再对经授权的 GitHub、GitLab
   目标各完成一次创建、读回、讨论、关闭往返；运行 Local、移交、Proposal
   只读、退役 bridge、阶段和完整校验。目标不可用时记录未验证范围，不能
   将模拟结果写成真实通过。

每个任务只推进一个可观察行为；前一任务的未知写入边界未通过时，不进入下一
任务的远端写入。远端无原子唯一键，只能通过完整查重、稳定标记、受管串行化和
读回降低重复风险；独立 clone 并发冲突须报告给人处理。

## 最小实现边界

- 先审查 `local_ticket_portability` 的目标验证、分页和响应校验，只复用能与
  Epiq 分离的小函数；不把完整交接器改造成通用 Tracker 框架。
- Issue 内容与私有意图使用不同于 Proposal 和 Local 移交的标记/存储边界。
  私有意图只保留对账字段，读回稳定身份后可清理；具体 schema 在任务 2 的
  红态测试与实现中确定。
- 不修改 Proposal、phase hook、Local 账本数据模型或旧 bridge。计划发现
  新的独立需求时另行评审，不把它悄悄加进本模块。

## 验证检查点

| 完成任务 | 必要证据 |
| --- | --- |
| 1 | 两平台只读查询与失败边界的聚焦测试；至少一个真实目标只读核对。 |
| 2 | 成功、4xx、超时、重复标记、跨会话及 linked worktree 用例均不重复创建。 |
| 3 | 合并未完成、部分覆盖、自动关闭和权限变化的逐项读回证据。 |
| 4 | Claude/Codex 入口和有限审查检查点在隔离消费者项目的场景记录。 |
| 5 | GitHub/GitLab 受控真实往返或明确未验证记录；`scripts/validate.sh` 及阶段、产物检查通过。 |
