# Spec: reflow-tolerant-replace

<!-- spec-guard: review approved 92c7ddcc41fc -->

## 目标

`managed-block.py` 判断「哪些行会被删掉」时逐行比文字（`replace` 约 162 行、`remove` 约 200 行）：旧块的某一行不在新模板、
也不在 `--known` 模板里，就算删减，要 `--accept-removals`。约定块模板 `claude-block-local.md` 有 12 行、`codex-block-local.md`
有 10 行缩进两格的续行。项目的 Markdown 格式化工具（oxfmt、Prettier 一类）把续行拼回单行后（只改空白，文字不变），拼出的整行
在模板里找不到，每次 `--replace` 都报一批「will remove … [needs --accept-removals]」。2026-11-02 在 0.86.1 上复现：装块、把
续行拼回单行、`--replace --dry-run`，报 11 条需要接受的删减，项目文件没变。teardown 用同一判据，同样会误报。

后果：用格式化工具的项目每次升级都要审一遍假删减，或者养成直接加 `--accept-removals` 的习惯，删减护栏形同虚设。

本模块让删减判定只看文字、不看折行和空白，同时把两份约定块模板改成每条规则一行。

给谁用：用 Markdown 格式化工具、并把约定块纳入格式化的项目；以及以后升级约定块的所有项目。

## 假设

用户已于 2026-11-02 确认（「比较归一化，两项都做」，针对本会话提出的两项修法）：

1. **按「段」比较，不按「行」比较。** 段是一个列表项或一个段落：遇到空行、或一行（去掉行首空白和 `>` 引用前缀后）以列表标记
   （`-`、`*`、`+`、`数字.`）、`#`、`|`、`<!--`、代码围栏开头时，开始新段；其余的行接到上一段。比较用的键是段的文字去掉全部
   空白、去掉续行的 `>` 前缀。只在比较时这样处理，写进文件的内容不变。
2. **适用于 `replace` 和 `remove` 两条路径**，以及 `--known` 模板（现行模板与已退役的派活规则段模板）；`--check`、`--dry-run`
   与真正写入用同一判据。
3. **真正删掉的文字照旧拦下**：旧块里有、新模板和 `--known` 里都没有的段，仍要 `--accept-removals`，否则拒绝且不改文件。
4. **预览按段列出**：`will remove:` / `will add:` 每段一行，显示该段拼成一行后的文字。只差折行或空白的段两边都不列。
5. **模板每条规则一行**：`claude-block-local.md`、`codex-block-local.md` 里缩进的续行拼到上一行，开头两行 `>` 引用拼成一行
   （中文与中文之间、中文标点之后不加空格，其余与英文、代码相邻处保留一个空格），文字不改；`docs/convention-block.md` 内嵌的块同步
   （`check-readme-sync.py` 要求逐字节一致）。已退役的派活规则段模板不改（只作 `--known`）。单行文字在 `proseWrap: 'never'` 下
   不再被改动，所以拼接处加不加空格都稳定。
6. **空行规则不变**（convention-block-blank-lines）：空行增减照旧单独报告；本地段原样保留；teardown 往返仍逐字节还原。
7. 发 0.86.2，只是修复，`interface.json` 不变。
8. 仓库里不出现消费项目的名字、模块或编号。

## 约定

### 判定

- 「只差折行或空白」：两段去掉全部空白（及续行的 `>` 前缀）后逐字相等。因此 `a b` 与 `ab` 视为相同；约定块是规则文字，
  不靠空格区分含义，接受这一点。
- 代码围栏内的行不拼接，每行自成一段（模板目前没有代码围栏，只为不把以后的代码块拼乱）。
- 段的切分只用于比较；`replace` 写入的仍是模板原文加本地段，`remove` 移除的仍是块内所有非本地段行。

### 升级路径（都不应要求 `--accept-removals`）

| 旧块 | 新模板 | 结果 |
|---|---|---|
| 0.86.1 模板原样（有续行） | 0.86.2（每条一行） | 替换，不报删减 |
| 格式化工具拼回单行后的 0.86.1 块 | 0.86.2 | 替换，不报删减；文件与模板一致后格式化工具不再改它 |
| 格式化工具拼回单行后的 0.86.1 块 | teardown | 移除，不报删减 |

## 测试策略

- 先写测试并确认在当前代码上失败，再实现。
- `test-setup-teardown.sh` 正反用例。夹具里的「格式化后」块由测试自己生成，不依赖外部格式化工具，生成方式照真实结果：
  每个软换行（换行加续行缩进、相邻两行 `>` 之间的换行）换成一个空格，所以中文标点后也会多一个空格：
  - 0.86.1 旧块（有续行）被拼回单行后：Claude 侧与 Codex 侧 `--replace --dry-run` 不列需要接受的删减，`--replace` 成功；
    teardown 预览与移除都不要 `--accept-removals`；
  - 0.86.1 旧块原样（有续行）升级到每条一行的新模板：同上；
  - 反例：拼回单行后再删掉一条规则里的几个字：仍要 `--accept-removals`，不接受时拒绝且文件不变；删掉整条规则：块里没有项目自己的
    文字被删，预览列出把它加回（`will add`），不要求接受；
  - 反例：只在一条规则里改一个词（文字不同）：照旧算删减加新增；
  - 本地段、空行增减、往返逐字节还原：既有用例全部通过。
- 变异：把比较改回逐行、去掉续行拼接，两处都必须让测试变红。

## 边界

- Always：先红后绿；只在比较时归一化，写入的文字取自模板；文字有出入就照旧拦下。
- Ask first：把归一化扩到块以外的文件内容；改本地段或空行规则；让 `--replace` 主动按项目的格式化风格写入。
- Never：为了不报删减而放宽到「文字不同也算相同」；在 Spec、代码、测试、提交信息或 PR 中写入消费项目的名称、模块或编号。

## 成功标准

- 格式化工具只改折行与空白时，`--replace`（含 `--dry-run`、`--check`）与 teardown 不再要求 `--accept-removals`。
- 块里与模板文字不同的段（拼行之后少了字、改了词）仍要 `--accept-removals`；块里缺了整条规则时预览列出加回，不要求接受。
- 两份约定块模板每条规则一行，`docs/convention-block.md` 同步，`check-readme-sync.py` 通过。
- 有续行的 0.86.1 旧块升级到新模板不报删减。
- 既有 setup/teardown 回归全部通过。

## 真实格式化结果（2026-11-02 由 ecosystem-lead 只读取自使用方仓库）

- 格式化工具 oxfmt 0.51.0，Markdown 相关配置只有 `printWidth: 80`、`proseWrap: 'never'`，约定块所在文件没有被排除。
- 段落与列表项里的软换行都拼成一行，换行处变成一个空格，中文标点后也会多出这个空格
  （如「`SPEC.md`、 `docs/SPEC.md`」）；模板开头两行 `>` 引用也拼成了一行。只把换行换成空格再逐行比对不上，
  所以判据去掉全部空白再比。
- 那次写入在 END 标记前留了一个空行，是 convention-block-blank-lines 的既定写法，不是格式化工具加的，本模块不改。
- 验收时用这份真实块（只含模板文字）做一次实测比对。

## 变更记录

- 2026-11-02（Task 1）：成功标准与测试策略里「删掉整条规则仍要 `--accept-removals`」改为「预览列出加回，不要求接受」。原因：`--replace` 遇到旧块缺一条规则时只是把它加回，块里没有项目自己的文字被删，删减护栏本就不该拦；写测试时发现原说法有误。最终验收附差异。
- 2026-11-02（Task 2）：模板拼行规则补「中文标点之后不加空格」。原因：照原规则拼会得到「`SPEC.md`、 `docs/SPEC.md`」这种标点后带空格的写法；只改空白，文字不变。最终验收附差异。
