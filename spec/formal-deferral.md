# Spec: formal-deferral

<!-- spec-guard: review approved 394046c26b72 -->

## 目标

一个模块的代码已经合入，只剩几项要等外部条件才能做（等某个外部服务、等另一边的真实入口、等别人给授权）。
现在这些项只能以未勾选项留在 `tasks/<id>/todo.md` 里：模块一直算「进行中」，项目到不了 DONE，依赖它的下游模块
在 `/map` 上永远不是「可以开始」（`map_view.py` 要求依赖全部 done）。`module-suspend` 解决的是「整个模块要等」，
挂起后下游算「阻塞」，不适用于「模块已经可用、只剩几项延期」。

实际使用中已经出现的情况（来源匿名化，2026-11-02 只读核对）：

- 两个项目里共 7 个已经合入主线的模块，因为 todo 里留着延期项，仍被算成进行中；一个项目的进度数显示 9/35，
  实际合入 12 个，下游被判为依赖没做完。
- 延期项各写各的：`- [ ] 延期 X-02 ……。原因：……`、`- [ ] D1：延期未验——……；缺外部授权`、
  `- [ ] E1 ……未验；责任方 ……；恢复需……`。多数已写了原因、责任方、恢复条件，只是字段名不一致。
- 另有两个模块把延期项挪到 `tasks/<id>/deferred.md`，借的是「阶段只数 todo.md」这个实现细节；
  `verify-artifacts` 对这种旁路清单本来就会警告（`rework-in-place`）。

本模块给延期一个正式写法：写明恢复条件的延期项不计入未完成，模块可以算完成、下游可以开工，延期项在 `/map`
与阶段提示里照样看得见，不会被当成遗漏。

给谁用：有外部依赖、需要「先放行下游、条件满足后回来补」的项目。

## 假设

用户已于 2026-11-02 确认：

1. **写法放在 todo.md 里**，不另设延期账文件；判据仍只读 todo.md 一份，恢复后照常勾选。
2. **没写恢复条件的延期项照旧算未完成**（宁可挡住），`verify-artifacts` 指出来。
3. **只剩延期项的模块算完成**，下游据此能开工；`/map` 与阶段提示显示「完成（延期 N 项）」并列出恢复条件。
4. **恢复靠人工**：条件满足后删掉「延期」前缀，模块回到构建中；hook 不判断条件是否满足。
5. **谁有权延期不归插件管**，由用户批准；gate 检查点不能延期，写了也照旧算未完成。
6. **迁移不自动改写**：`verify-artifacts` 对疑似延期的自由文本与旁路 `deferred.md` 给提示和改写示例；
   旁路文件不被认作延期账。
7. 改所有读 todo 勾选状态的地方，补正反回归，更新模板与文档，按 minor 发版；发版前把口径变化告诉总负责人。
8. 仓库里不出现消费项目的名字、模块或编号。

## 约定

### 写法

延期项是一个**未勾选**的清单项，正文以延期前缀开头，并带恢复条件：

```markdown
- [ ] 延期：<事项>；恢复条件：<条件>
- [ ] Deferred: <item>; Resume when: <condition>
```

- 前缀：`延期` 或 `Deferred`（大小写不敏感），后接 `：` 或 `:`。
- 恢复条件：`恢复条件` 或 `Resume when`（大小写不敏感），后接 `：` 或 `:`，前面用 `；` 或 `;` 与事项隔开；
  冒号后至少一个非空白字符。
- 两种语言可以混用（`延期：…；Resume when: …` 也算），与项目的 `artifactLanguage` 无关。
- 事项部分可以写原因、责任方等任意文字；插件只取「事项」与「恢复条件」两段，不解析其他字段。
- 已勾选（`[x]`）的项不论写什么都按已完成算，不算延期。

**不算延期、照旧计为未完成**（失败方向是挡住，不是放行）：

- 没有恢复条件段，或恢复条件为空；
- 事项以 `检查点`／`Checkpoint` 开头，或带 `（gate）`／`（report）` 层级标注（检查点不能延期）；
- 写在 todo.md 以外的文件里。

旧版插件读到这种写法时把它当普通未勾选项（模块仍算进行中），不会误判为完成。

### 判据（唯一实现）

- `module_stage` 新增延期项的唯一判据（一个正则加一个取出「事项／恢复条件」的函数），其他文件只导入不复写。
- `UNCHECKED`（以及 `OPEN_ITEM`）不再匹配合格的延期项。所有导入它们的地方因此一致：阶段计算、`/map` 进度、
  下一个 gate、最终 gate、`gate-tick` 的剩余计数、`module-suspend` 的「没有未勾选项」、`module-insert` 的
  「做到一半」、`verify-artifacts` 的挂起标记过期判断。Plan 阶段逐个核对这些调用点，有不该跟着变的单独列出。
- `module_state` 增加 `deferred`：合格延期项的列表（事项与恢复条件，按出现顺序）。`open` 不含延期项。
  只剩延期项、且有 Plan 的模块 `stage` 为 `DONE`。
- 挂起标记与延期项可以同时存在：挂起只看非延期的未勾选项；只剩延期项时挂起标记按「过期」处理（与今天无未勾选项时一致）。

### 阶段提示

- 有延期项的模块：计数行末尾追加 ` · 延期 <n>`（英文 ` · Deferred <n>`），`<n>` 是全项目合格延期项总数。
- 项目为 `DONE` 且有延期项时，下一步建议说明「未完成项都已做完，另有 <n> 项延期待恢复」并指向 `/map`，
  不说成「没有任何未勾选项」。不在每轮注入里逐条列出延期项（列表在 `/map`）。
- 没有任何延期项时，所有现有输出逐字节不变。

### `/map`

- 表格：有延期项的已完成模块显示为「已完成（延期 <n>）」；进行中的模块的进度 `x/y` 不把延期项算进 `y`。
- 表格下方新增「延期项」一节：按 Build order 列出每个模块的延期项与恢复条件；没有延期项时这一节不出现。
- JSON（`schemaVersion` 仍为 1，只增字段）：每个模块加 `deferred: [{"item", "resumeWhen"}]`（没有时为空列表），
  顶层加 `deferredTotal`。`status` 的取值不变，只是只剩延期项的模块从 `in_progress` 变成 `done`，
  下游从 `not_ready` 变成 `ready`——这是本模块要改的口径。
- `interface.json` 版本升到 1.12，写明新增字段和口径变化；`validate.sh` 的一致性检查覆盖新字段。

### `verify-artifacts`

- **失败**：todo.md 里带延期前缀、却缺恢复条件或恢复条件为空的未勾选项（指出文件与行号，给出正确写法）；
  带延期前缀的检查点项。
- **警告（迁移提示，不判失败）**：
  - todo.md 里未勾选、正文含「延期」或 `deferred`（大小写不敏感）但不符合正式写法的项：
    给出改写示例 `- [ ] 延期：<事项>；恢复条件：<条件>`，说明不改写就继续算未完成；
  - `tasks/<id>/` 下 `plan.md`、`todo.md` 之外的文件里有合格延期写法或含「延期」的未勾选项：
    说明它们不被认作延期，请挪回该模块的 todo.md（沿用 `rework-in-place` 那条旁路清单警告，补一句延期的说法）。
- 同一判据在 phase-guard 与 verify-artifacts 两边都有正反回归。

### 规则与文档

- 共享检查点规则补一条：外部依赖类的未完成项，经用户同意可写成延期项；写明恢复条件；恢复条件满足后删掉前缀
  继续做。约定块模板（中英）各加一行写法说明。
- `docs/design.md`（阶段判据）、`docs/workflow.md`、README 中英、CHANGELOG 同步；版本号升到 0.86.0。

## 测试策略

- 先写测试并确认在当前代码上失败，再实现。
- 判据：合格写法（中、英、混用、全角／半角标点、大小写）算延期；缺恢复条件、恢复条件为空、检查点、已勾选的不算。
- 阶段：只剩延期项的模块为 DONE，下游为 ready；延期项与普通未勾选项并存时仍为 BUILDING，`open` 不含延期项；
  删掉前缀后回到 BUILDING。
- 输出：计数行、DONE 建议、`/map` 表格与延期项一节、JSON 新字段；无延期项时逐字节不变。
- 其余调用点：gate-tick 剩余计数、module-suspend、module-insert 的做到一半、下一个 gate／最终 gate 跳过延期项。
- verify-artifacts：缺条件失败、检查点延期失败、自由文本与旁路文件给提示、合格写法通过。
- 变异：判据去掉「必须有恢复条件」、`UNCHECKED` 不排除延期项、DONE 建议不区分延期，三处都必须让测试变红。

## 边界

- Always：先红后绿；延期判据只在 `module_stage` 一处；hook 只读；无延期项时行为不变。
- Ask first：给延期加日期、责任方等结构化字段；让 hook 判断恢复条件是否满足或按时间提醒；自动改写现有写法；
  认 todo.md 以外的延期账文件。
- Never：自动把未勾选项改成延期项；把没有恢复条件的项当成延期；在 Spec、代码、测试、提交信息或 PR 中写入
  消费项目的名称、模块或编号。

## 成功标准

- 一个模块只剩合格延期项时，阶段提示与 `/map` 都算它完成，依赖它的下游在 `/map` 上为「可以开始」。
- 每个延期项与恢复条件在 `/map` 上看得见；项目 DONE 时阶段提示说明还有几项延期。
- 写错的延期项（缺恢复条件）不会放行，`verify-artifacts` 指出位置与正确写法；现有自由文本与旁路文件得到迁移提示。
- 没有延期项的项目所有既有回归逐字节通过。
- 发版前已把口径变化（哪些模块会从进行中变为完成、下游变为可以开始）告诉总负责人。
