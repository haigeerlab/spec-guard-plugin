# Spec: hub-only-reply

<!-- spec-guard: review approved 3a1a7db4d225 -->

## Objective

0.80.0 起，交审在模块会话的对话正文里放一个推荐答复的复制块。接了决策收件箱的项目里，要用户决定的事本来就由收件箱问；
模块会话也放复制块后，一个真实项目的演练里用户在模块协调会话和决策收件箱各答了一次，撤回和结项撞在一起。

本模块给「交审时说明怎么批准」加一条让步规则：使用方插件规定要用户决定的事只在收件枢纽问时，模块会话照常给内容，但不放
复制块，改为指向收件箱。只加规则文字，不加检测。

登记：2026-10-19 经 `module-insert.py` 插入能力图，用户在本会话批准插入。需求来自决策收件箱一方补的 SG-2 限定，用户已回
「可以」；做法（只加一句让步规则、不做检测）由用户定，经 spec-guard 插件负责人会话转来。

## Assumptions

1. **按意思认，不按字面匹配。** 两个使用方插件写这条规定的说法不同：一个写「只在决策收件箱问」，另一个写「要用户决定的事
   经模块协调送到决策收件箱问，下一步框里不放决定按钮」。规则写成「只在收件枢纽问，或经协调会话送到那里问」，两种都算。
2. **只拿掉复制块，内容一项不少。** 小项、“注意：”“批了会怎样：”、各选项选了会怎样与推荐理由照常写在正文里；只把推荐答复的
   复制块换成一句「去决策收件箱答 #N」，不知道事项号写「去决策收件箱答」。使用方插件已在用的「等决策收件箱答复」意思相同，任选。
3. **没有这种规定时照旧放复制块。** spec-guard 不判断项目接没接收件枢纽：同一文件「经收件枢纽转来的批准」一节写明 spec-guard
   不登记收件枢纽，接没接由使用方插件决定。所以 agent 读到使用方插件的这条规定才让步。
4. **卡住时选做法也跟着让步。** 「第二次过不去」那条写的是推荐答复「按「交审时说明怎么批准」放进可复制代码块」，引用的是同一条规则，
   不另改。
5. **不改的地方**：不加检测代码、不改判据，不碰 phase-guard 与 verify-artifacts。`interface.json` 只改 `reviewKinds` 的说明文字，
   在「推荐答复放在一个可复制代码块里」一句后补上收件枢纽的例外；不改字段，不改接口版本 1.5。
6. **不改版本号、不发版**；CHANGELOG 写进「[未发布]」段。

## Contract

`references/workflow-checkpoints.md`「批准标记」一节，「交审时说明怎么批准」一条末尾加：

> 使用方插件（例如决策收件箱、module-crew）规定要用户决定的事只在收件枢纽问，或经协调会话送到那里问时（按意思认，不按字面匹配
> 某一句），交审照常在正文里给全部小项、“注意：”“批了会怎样：”、各选项选了会怎样与推荐理由，但不放推荐答复的复制块，改写一句
> “去决策收件箱答 #N”（不知道事项号就写“去决策收件箱答”；“等决策收件箱答复”意思相同，任选一种）。没有这种规定时照旧放复制块。
> spec-guard 不判断项目接没接收件枢纽，按使用方插件的规定办（见「经收件枢纽转来的批准」一节）。

三处镜像各补半句「使用方插件规定只在收件枢纽问时不放复制块，改写去决策收件箱答」：`commands/review-mark.md`、
`skills/spec-guard-ops/SKILL.md`、`docs/commands.md`。`CHANGELOG.md`「[未发布]」段加一条。

## Testing strategy

- 先加断言并确认失败：`test_workflow_checkpoints.py` 的「交审时说明怎么批准」用例补关键词（只在收件枢纽问、经协调会话送到那里问、
  按意思认、不放推荐答复的复制块、去决策收件箱答 #N、不知道事项号、等决策收件箱答复、没有这种规定时照旧放复制块、
  经收件枢纽转来的批准）；镜像用例补「去决策收件箱答」。
- 已有断言不改、全部通过。
- 变异核对：在副本上删掉这句，确认断言变红。

## Boundaries

- Always：规则只在共享检查点规则写一处，镜像只摘要。
- Ask first：加检测或钩子；改 `interface.json` 里 `reviewKinds` 说明文字以外的内容（字段、接口版本 1.5）。
- Never：仓库文件、提交信息或 PR 中写私有项目名；改插件版本号；让模块会话在这种场景下少给任何一项内容。

## Success criteria

- AC1：「交审时说明怎么批准」有这条让步规则，写明两种说法都算且按意思认、内容一项不少、不放复制块、改写「去决策收件箱答 #N」
  （不知道事项号的写法、与「等决策收件箱答复」同义）、没有规定时照旧放复制块、spec-guard 不判断接没接收件枢纽；回归断言先红后绿。
- AC2：三处镜像都带「去决策收件箱答」；回归断言覆盖。
- AC3：不改 `hooks/` 下的判定代码（测试文件除外）；`interface.json` 只改 `reviewKinds` 的说明文字，不改字段，不改接口版本 1.5；
  已有断言不改且全部通过。
- AC4：全套检查通过，插件版本号仍为 0.80.0，CHANGELOG 只写「[未发布]」段。
