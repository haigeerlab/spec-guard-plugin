# Spec: linked-project-root

<!-- spec-guard: review approved 193266aa1619 -->

## Objective

阶段钩子只看会话所在目录（及其 git 根）：那里没有约定块、也没有带 `activeModule` 的 `state.json`，就按无关项目静默退出。
2026-10-13 的实地报告记录了一种用法：会话开在一个纯需求文档目录，实际开发的仓库在另一个路径。整个开发过程中
那个会话没有收到过一次自动阶段注入，agent 只在自己想起来时手动跑过几次钩子脚本；用户并不知道守卫没有生效。

钩子无从得知会话在操作哪个别的目录。核对过宿主提供的信息：Codex 会话记录里的工作区根目录只有会话目录本身，不包含
agent 实际在改的项目；从会话记录推断属于猜测，会认错项目。静默本身符合“无激活信号的无关项目必须静默退出”这条不变量，
问题在于没有任何办法声明“这里的工作对应那个项目”。

本模块提供显式指向：一个命令在会话目录写下指向文件，钩子据此改读被指向的项目。指向文件是插件写下的激活信号，
没有它的目录照旧静默。

登记：2026-10-13 经 `/spec-guard:add-module` 插入能力图。

## Assumptions

用户已于 2026-10-13 确认：

1. 采用显式指向（不推断、不对无信号目录给提示）。范围是阶段钩子加指向命令；各命令自动跟随指向留给后续模块。
2. 指向文件是会话目录的 `.agent/spec-guard-link.json`，只含版本号与项目路径；路径可以是绝对路径，也可以是相对于会话目录的
   相对路径。
3. 新命令 `/spec-guard:link-project`（Codex 走 `spec-guard-ops` 的对应一节）：查看、建立、解除；建立与解除先预览、确认后才写；
   只写这一个文件，不动被指向的项目。
4. 建立时目标必须存在且已启用 spec-guard，否则拒绝；会话目录自己已启用 spec-guard 时也拒绝。
5. 钩子的判断顺序：会话目录自己有激活信号时照旧并忽略指向文件；自己没有激活信号且有指向文件时才读被指向的项目；
   不连环跟随。
6. 注入里多一行写明项目位置、当前会话目录指向它，并提示运行 spec-guard 命令时带上该项目路径；其余内容是那个项目自己的
   阶段提示。
7. 指向失效时给一行诊断，不静默：格式不对、目标不存在、目标未启用各有说明。
8. 默认不入库：预览提示该文件含本机路径、建议加进 `.gitignore`；命令不改 `.gitignore`。
9. `spec-guard-ops` 补一句：会话目录有指向时，运行各命令要带上被指向的项目路径。
10. 不做：命令自动跟随指向；从会话记录推断项目；Codex 两处插件副本的差异。
11. 版本 0.58.0，一个 PR。发版后在 Codex 上用“会话目录不是项目目录”的形态做一次真实会话验证。

## Contract

### 指向文件

`<会话目录>/.agent/spec-guard-link.json`：

```json
{"version": 1, "project": "<路径>"}
```

- “会话目录”与钩子现行的定位相同：宿主给的项目目录，或会话 cwd 所在的 git 根，不在仓库里时是 cwd。
- `project` 是非空字符串；相对路径相对于会话目录解析。解析后的目标取其真实路径。
- 只认这两个键；多余的键、`version` 不是 1、不是 JSON 对象、`project` 不是非空字符串，都算格式无效。

### 钩子

`phase-guard.sh` 在激活判断处：

| 会话目录 | 指向文件 | 行为 |
|---|---|---|
| 有约定块或 `state.json` 激活信号 | 任意 | 与现行逐字相同，不读指向文件 |
| 没有激活信号 | 不存在 | 静默退出，与现行相同 |
| 没有激活信号 | 存在且有效，目标已启用 | 以目标为项目根输出阶段提示，并多一行 `Linked project` |
| 没有激活信号 | 存在但失效 | 输出一行诊断（合法的 hook JSON），不输出阶段 |

- 失效的三种情况各有固定文字：格式无效；目标目录不存在或不是目录；目标没有 spec-guard 激活信号。诊断指出指向文件的位置
  与修正办法（重新运行指向命令或解除指向），不把文件内容原文带进注入；目标路径经现有的清洗后给出。
- 不连环跟随：只看目标自己的激活信号，不读目标里的指向文件。
- `Linked project` 一行含目标路径与会话目录，并说明运行 spec-guard 命令时要把该路径作为项目传入。位置行（分支与 worktree）
  报告的是目标项目的。
- 指向文件存在而 `python3` 不可用时，沿用现有“已启用但缺 python3”的非静默提示；没有指向文件时不因此多做任何事。
- 钩子仍然只读，仍只依赖 bash、git 与 python3。

### 命令

`/spec-guard:link-project`，实现为 `hooks/project_link.py`：

```text
project_link.py show   --from <会话目录>
project_link.py set    --from <会话目录> --project <路径> [--confirm]
project_link.py unset  --from <会话目录> [--confirm]
```

- `show`：有没有指向、指向哪里、当前是否有效（及无效的原因）。只读。
- `set`：预览将写入的文件与内容、解析后的目标、目标的当前阶段，并提示该文件含本机路径、建议加进 `.gitignore`；
  `--confirm` 才原子写入并读回。按给定的写法保存路径（相对的仍存相对的）。
- `unset`：预览后 `--confirm` 才删除指向文件；`.agent/` 因此变空时不删目录。
- 拒绝（退出码 2、不写文件）：目标不存在或不是目录；目标没有激活信号；会话目录自己有激活信号；目标就是会话目录；
  已有指向文件格式无效（提示先 `unset`）；`unset` 时没有指向文件。
- 不改 `.gitignore`、不动目标项目、不执行 Git 或远端操作。

### 规则与文档

- `spec-guard-ops` 新增 link-project 一节，并在技能开头的项目定位说明里补一句：会话目录有指向时，各命令的 `--project`
  用被指向的项目路径。
- `docs/commands.md` 登记；`docs/troubleshooting.md` 加“会话目录不是项目目录，阶段提示不出现”与三条诊断的处理；
  `docs/design.md` 的激活信号一节补指向文件；CHANGELOG `[未发布]`；版本号 0.58.0。

## Testing strategy

- 先写测试并确认在现有代码上失败，再实现。
- `test-phase-guard.sh`：上表四行各一例；三种失效各一例且输出是合法 hook JSON；不连环跟随；相对路径；会话目录自己已启用时
  与没有指向文件时输出逐字相同；**没有指向文件的无关目录仍然静默**；`Linked project` 行恰好一行；两边宿主各一例。
- `test_project_link.py`：`show` 的三种状态；`set` 预览不写文件、`--confirm` 写入并读回、重复执行结果相同；`unset`；全部拒绝情况。
- 判据是否真能拦住回归：在草稿副本上分别改坏“自己已启用时忽略指向”“目标必须已启用”“不连环跟随”三处，确认相应断言变红。
- 宿主行为：发版后在一个临时目录结构上（会话目录无约定块、项目在别处并已启用）用 `codex exec` 与 `claude -p` 各跑一次，
  确认会话读到被指向项目的阶段与 `Linked project` 行。阶段行不属于无人值守时省略的内容，可以无界面验证。

## Boundaries

- Always：没有指向文件且没有激活信号的目录静默；会话目录自己已启用时行为逐字不变；钩子只读；失效时报诊断而不是静默，
  也不把失效说成“项目未启用”。
- Ask first：让命令自动跟随指向；让钩子在没有任何信号时给提示；连环跟随；由命令修改 `.gitignore`。
- Never：从会话记录或工具调用推断项目；把指向文件原文带进注入；在 Spec、代码、测试、提交信息或 PR 中写入消费者项目的
  名称、路径、模块或编号。

## Success criteria

- 会话目录不是项目目录时，建立一次指向后，每轮都能收到被指向项目的阶段提示，并看到项目位置。
- 没有指向文件的无关目录、以及自己已启用的项目，输出与现行逐字相同。
- 指向失效时用户能从一行诊断知道是哪一种失效、怎么修。
- 建立与解除都先预览后确认，只动指向文件。
- 三条最小验证与 ShellCheck 全部通过；真实宿主上各验证一次。
