# 审查报告

本目录保存对 `spec-guard` 的正式、可追溯审查结论。它回答的是“当前版本是否值得使用、风险在哪里、下一步修什么”，而不是描述将来要实现的功能。

## 边界

- `docs/reports/`：审查范围、证据、评分、发现的问题与收口状态。
- `spec/`：某项能力将要满足的行为契约。
- `tasks/`：实现某个已确认规格的执行计划。
- `docs/releases/`：某个版本的构建、安装与验收证据。

早期的研究笔记（原 `docs/research/`）与 2026-09-12、09-13 的早期报告已从仓库删除，可在 git 历史中查看。

报告不是第二个任务事实源。需要进入正式 tracker 的条目，仍应由获授权的维护者按项目流程创建；报告只提供可直接转化为 issue 的证据和验收条件。

## 命名与最低内容

文件名使用 `YYYY-MM-DD-<scope>-audit.md`。每份报告至少写明：审查范围与基线、证据和未验证边界、评分口径、按风险排序的问题清单、建议修复顺序，以及每项的收口条件。

涉及外部服务时，必须说明是否实际访问或写入。本仓报告不得把本地桩或源码推导表述为线上验证。
