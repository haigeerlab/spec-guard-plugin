# v0.16.2 公开来源恢复

## 状态

Spec Guard 的公开安装来源恢复为
[`yizhongkaimail-collab/spec-guard-plugin`](https://github.com/yizhongkaimail-collab/spec-guard-plugin)。
这不是 GitHub repository transfer：恢复保留已有 yizhong 仓库的历史与 Issue，并以不使用
`--force` 的快进方式接续当前源码和发布标签。

旧来源无法作为后续 marketplace 更新端点时，已安装的缓存副本不会被本次变更修改；它们可继续
运行，直到维护者或使用者显式迁移来源。

## 使用者迁移

在有权修改本地 Codex marketplace 配置的机器上，先移除旧 marketplace 条目，再添加新的公开
来源并重新安装 Spec Guard。不要把缓存副本、历史 GitHub Release 链接或旧发布证据误当作新来源
的可达性证明。

Codex 的具体命令和版本以当时 `codex plugin marketplace --help` 为准；在更新前确认新的
marketplace snapshot 指向 `yizhongkaimail-collab/spec-guard-plugin`，并在新会话验证已启用版本。

## 维护者边界

- 不重写旧的 Release、证据文档、Issue 或 Git 历史；其中的旧链接仍是历史记录。
- 不把旧发布资产自动声明为已在新来源重新发布；如需保留某个旧版本资产，须单独重新托管并明确
  标注其恢复来源。
- 新的发布从 yizhong 来源创建 tag、Release 和资产，并按正常宿主安装流程核验。
